# 処方ブリッジ（本格版）設定手順

Supabase（データベース・会員管理）と、公開用のサイトで動く版です。
インドネシア側は **メールアドレスとパスワードだけ** で使えます（Claude のアカウントは不要です）。

## できていること

| 項目 | 状態 |
|---|---|
| データベース（案件・依頼・提出・完成処方・企画書） | 作成済み（Supabase プロジェクト `formula-bridge`、シンガポール） |
| 会社ごとの閲覧制限（A社はB社の依頼を見られない・書き換えられない） | 作成・検証済み |
| 企業登録（会社名・担当者・連絡先・パスワード・NIB・ハラール・秘密保持同意） | 作成済み |
| マスター画面（全社の状況・依頼内容・進捗） | 作成済み |
| 依頼ボタン → 相手企業へリンク付きメール | 仕組みは作成済み。**メールサービスの設定待ち** |
| 提出 → 当社の開発専用メールへ自動通知 | 仕組みは作成済み。**メールサービスの設定待ち** |
| 翻訳・日本語表示名称への変換・企画書作成（AI） | 仕組みは作成済み。**APIキーの設定待ち** |
| 市場データ（出典付き） | 登録済み |
| サンプル発送（運送会社・追跡番号）→ 当社の開発専用メールへ自動通知 | 作成済み（メール設定待ち） |
| 当社からのフィードバック（必須・英語／インドネシア語に自動翻訳して相手へメール） | 作成済み。未実施はマスター画面に赤で表示 |
| 登録時の3つの合意（NDA／当社の原料購入宣言／採用処方の帰属） | 作成済み。英語・インドネシア語併記、同意日時を記録 |
| BIOTのロゴ | 表示枠を作成済み。**ロゴ画像の差し替え待ち**（`web/logo.png`） |

## 社長にお願いする作業（上から順に）

### 1. サイトを公開する（Vercel・無料）
1. https://vercel.com を開き「Sign Up」→「Continue with GitHub」でログインします。
2. 「Add New…」→「Project」→ リポジトリ `biot-simulator` の「Import」を押します。
3. 「Root Directory」の「Edit」を押し、`apps/formula-bridge/web` を選びます。
4. 「Framework Preset」は「Other」のまま、「Deploy」を押します。
5. 完成すると `https://〜.vercel.app` のURLが表示されます。これが処方ブリッジのURLです。

### 2. Supabase にサイトのURLを登録する
1. https://supabase.com/dashboard/project/hskwwaziaplysoepqxiy を開きます。
2. 左メニュー「Authentication」→「URL Configuration」を開きます。
3. 「Site URL」に手順1のURLを入れて保存します。
4. 「Redirect URLs」に `手順1のURL/**` を追加します。

### 3. AI の鍵（APIキー）を登録する
1. https://console.anthropic.com →「API Keys」→「Create Key」で鍵を作ります（`sk-ant-…` で始まる文字列）。
2. Supabase の左メニュー「Edge Functions」→「Secrets」で、名前 `ANTHROPIC_API_KEY`、値に鍵を入れて保存します。
3. 企画書（STEP 4）は Gemini（市場調査）と GPT（査読）も使います。同じ「Secrets」に次を登録します（無いときはその工程を省略して作成します）。
   - `GEMINI_API_KEY`：Google AI Studio の鍵。**課金を有効にしたプロジェクトの鍵を使うこと**（無料枠は送信内容が学習に使われる場合があるため、機密資料には使わない）。
   - `OPENAI_API_KEY`：OpenAI の鍵（`sk-…`）。
   - 任意：`GEMINI_MODEL`（既定 `gemini-3.1-pro-preview`）、`OPENAI_MODEL`（既定 `gpt-5`）。新しいモデルに変えるときは、ここにモデル名を入れるだけで切り替わります。

### 4. メール送信の設定（Resend）※送信元アドレスが決まってから
1. https://resend.com に登録し、「Domains」で会社のドメインを追加します。
   表示される DNS の設定を、ドメインの管理会社の画面に貼り付けます。
2. 「API Keys」で鍵を作ります（`re_…` で始まる文字列）。
3. Supabase「Edge Functions」→「Secrets」に、名前 `RESEND_API_KEY` で登録します。
4. Supabase「Authentication」→「Emails」→「SMTP Settings」で「Enable custom SMTP」をオンにして、次を入れます。
   - Host: `smtp.resend.com`　Port: `465`　Username: `resend`　Password: 手順2の鍵
   - Sender email: `noreply@御社ドメイン`　Sender name: `Formula Bridge`
   → これで、インドネシア側の **登録確認メール** と **パスワード再設定メール** が届くようになります。

> **それはNG**：「Confirm email（メール確認）」をオフにしてはいけません。オフにすると、他人が社長のメールアドレスで先に登録して管理者になりすませてしまいます。

### 5. 管理者アカウントを作る
1. 処方ブリッジの「設定」→「管理者のメールアドレス」にアドレスを追加し、「招待メールを送る」を押します。
2. 相手は届いた招待メールのリンクを開き、パスワードを決めると管理者になります。
   （最初の1人目は、Supabase の「Authentication」→「Users」→「Add user」で、管理者リストにあるアドレスを「Auto confirm」付きで作成します。）
   ※ 自分で新規登録する画面はありません。登録画面から管理者になることはできません。

### 6. 設定画面で開発専用メールを入れる
マスター画面の「設定」で次を入れて保存します。
- 開発専用メールアドレス（インドネシア側の提出がここに届きます）
- 送信元（例：`処方ブリッジ <noreply@御社ドメイン>`）
- このサイトのURL（手順1のURL）

### 7. インドネシアの仕入先を登録する
1. 「登録企業」画面で、会社名・担当者名・担当者のメールアドレスの3つだけを入れて「登録してログイン情報を発行」を押します。
2. 表示された案内文（URL・メールアドレス・仮パスワード入り、英語とインドネシア語）を相手に送ります。
   仮パスワードはメールではなく、口頭や社内チャットなど別の手段で伝えてください。
3. 相手は初回ログイン時に、3つの合意への同意、自分のパスワード設定、会社情報と会社ロゴ（JPG）の入力を必ず行います。
4. 相手がパスワードを忘れた・仮パスワードが届かなかったときは、「登録企業」の一覧でその会社の「仮パスワードを再発行」を押します。新しい仮パスワード入りの案内文が表示されるので、同じく口頭や社内チャットで伝えてください（メール送信の設定前でも使えます）。
5. 登録の途中で通信が切れた場合も、同じ内容でもう一度登録すれば自動で修復されます。一覧に会社が出ていれば登録は完了しています。
6. 相手は3つの合意に同意するまで、依頼内容を一切見られません（データベース側でも制限しています）。

## ロゴの差し替え
`web/logo.png`（横長、高さ72px以上の透過PNGがおすすめ）を置くと、ログイン画面と上部バーに表示されます。
ファイルがない間は「BIOT」の文字ロゴが表示されます。

## 日本語表示名称（成分表示名称）の確認のしくみ
- 「日本語表示名称に変換」を押すと、AIがインターネットで粧工連（日本化粧品工業会）の成分表示名称リストなどを調べます。
- その後、**サーバーが出典ページを自分で開き**、INCI名と表示名称が並んで載っているかを機械的に確かめます。AIの答えだけでは「確認済み」にしません。
  - 「✓ 粧工連リストで確認」：jcia.org のページで確認できたもの
  - 「✓ Web出典で確認」：jcia.org 以外のページで確認できたもの（リンクから出典を確認できます）
  - 「要確認」：出典で確認できなかったもの（AIの推定）。完成処方に警告が表示されます（確定は可能）。
- 確認済みの名称は辞書（データベースの label_names 表）に保存され、次回からは同じ答えがすぐに出ます。
- 「要確認」の名称は、担当者が出典や粧工連リストで目視確認したうえで、STEP 3 の完成処方の「確認済みにする」を押すと「✓ 当社で確認」になり、確認者名とともに辞書に保存されます。
- 辞書の中身は「設定」→「表示名称の辞書」で確認でき、誤りは削除できます（削除すると次回は改めて調べ直します）。
- STEP 3 の「全原料の表示名称を確認」で、採用処方と当社追記分をまとめて確認できます。当社で入力した名称が出典と異なる場合は指摘します。
- 最終的な製品表示の前には、必ず担当者が出典リンクで目視確認してください。

## 翻訳の確認のしくみ
- 依頼書・フィードバック・翻訳ツール・提出内容の日本語訳は、訳したAIとは別のAI（GPTが使えるときはGPT、使えないときは確認専用のClaude）が原文と照合し、誤訳・抜け・数値の違いを直します。
- 数字は機械的にも照合し、訳文に見当たらない数字があれば表示します。
- 送信前の確認画面に、指摘内容と「訳し戻した日本語」が表示されます。

## 使い方の流れ
1. マスター画面 →「＋ 新規案件」→ STEP 1 で依頼内容を記入 →「依頼書を作成」
2. 依頼先の会社にチェックを入れて「依頼を送る」→ 各社にリンク付きメールが届く
3. 各社は自社あての依頼だけを開き、英語で入力して「Submit to Japan」→ 開発専用メールに通知
4. 各社がサンプルを日本へ送り、追跡番号を入れて「Shipment complete」→ 開発専用メールに追跡番号つきで通知
5. サンプル到着後、STEP 2 で判定とコメント（日本語）を入れて「英訳・インドネシア語訳して送る」→ 相手にメール（**必須**）
6. STEP 2 で各社の提出内容を比較 → STEP 3 で採用する会社を選び、当社の原料を追記して確定
7. STEP 4 の「出来上がり」→ PowerPoint・Word を保存

## 技術メモ（開発者向け）
- 画面: `web/`（ビルド不要の静的サイト。ライブラリは `web/vendor/` に同梱）
- DB: `supabase/migrations/`（行レベルセキュリティで会社ごとに分離）
- サーバー処理: `supabase/functions/ai`（Claude API、モデル `claude-opus-5`、拒否時の自動フォールバック有効）、`supabase/functions/notify`（Resend でメール送信）
